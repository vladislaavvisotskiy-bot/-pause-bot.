# PAUSE delivery bot — working notes

Telegram bot + two Mini Apps on one aiohttp process:
- **PAUSE App** (`pauseapp.py`, `pauseapp_static/`) — client-facing ordering app, mounted at `/pauseapp`.
- **Маршрут** (`webapp.py`, `webapp_static/`) — courier/route-admin app, mounted at root/`/miniapp`.
- `sheets.py` — all Google Sheets I/O (both apps share it). `config.py` — sheet/column constants.
- No real Google Sheets credentials exist in this sandbox — verify sheets.py logic with small hand-rolled `FakeWs`/`FakeRequest` scripts in the scratchpad, not live calls.

## Usage economy (explicit standing instruction)

The user is on a Pro plan with a limited weekly quota shared across all Claude usage (chat + Claude Code, cloud + local). Work deliberately to spend less per task, without lowering the quality of what ships:

- **Stay scoped.** Touch only what the request requires. Don't audit, "while I'm here" refactor, or re-verify unrelated code unless asked.
- **Don't re-read after a successful Edit/Write.** The tool result already confirms the change landed — re-reading the file to double-check is wasted tokens unless you need to see surrounding context you don't already have.
- **Read narrowly.** Prefer `Grep` (with line numbers / limited context) or `Read` with `offset`/`limit` over reading whole large files (`sheets.py`, `webapp.py`, `webapp_static/app.js`, `pauseapp_static/app.js` are thousands of lines each) when you only need one function or section.
- **One pass of verification, not several.** Write the isolated test, run it once, fix what it finds, move on — don't re-run tests repeatedly "just to be sure" when nothing changed since the last green run.
- **No subagents for small/medium tasks.** This is a single, well-understood codebase — delegate to the Agent tool only for genuinely large, independent, multi-file investigations, never for routine bug fixes.
- **Batch related fixes into one commit/response** instead of back-and-forth micro-turns, when the user already described everything needed.
- **Ask only when truly blocked** (ambiguous requirement, destructive action, missing credential) — don't ask clarifying questions answerable by reading the code yourself.
- **Keep prose replies short.** Skip restating the request back, skip long preambles — state what changed and what's next.
- **No screenshots unless asked** (explicit user instruction, don't render/send preview images on your own). Keep replies minimal: a few lines on what changed + the deploy reminder only if relevant. Skip visual preview renders unless the user asks to see something.

**Non-obvious gotchas hit this session, worth remembering:**
- Google Sheets `SUMIF`/`SUM` silently skip text-typed cells even if they look numeric — `append_order`/`append_orders_batch` now write `O_QTY` as a real `int`, not `str()`, because Sheet1's "Кол-во Заказов" column is a `SUMIF` over that column (this is why order counts could look "stuck" even with real confirmed orders — see `sheets.migrate_order_qty_to_numbers()` / `scripts/fix_order_qty.py` for the one-time historical-data fix, must be run somewhere with real Sheets credentials, not in this sandbox).
- `openProfileSubscreen(title, loaderFn)`'s `sub` container starts with a skeleton-block child already inside it — any `loaderFn` that renders synchronously (not through an async `api()` call) must do `sub.innerHTML = ""` itself first, or the skeleton lingers above the real content.
- `tg://user?id=...` deep links (Telegram "Написать" buttons) only resolve if the viewer's Telegram client already has that user cached locally — prefer the `https://t.me/<username>` form routed through `WebApp.openTelegramLink()` (see `openTelegramChat` in `app.js`), falling back to `tg://` only when no username is known.

## Mini App-only mode (prepared, OFF by default)
`BOT_MINIAPP_ONLY=1` (+ `WEBAPP_URL`) → clients get ONE button "Открыть PAUSE" in the bot (couriers also "Маршрут"); old buttons/texts are caught by `handlers/legacy.py` (first router) and answered with a warm rebrand message + app button (8 s cooldown per user); bot menu button → app; menu publish (bot or Ops Center) auto-starts `menu_broadcast.start` (skips clients with notify_menu_off, skips if that date was already broadcast per log sheet "Рассылки меню", reports sent/failed/skipped to the admin in the bot); the manual "Рассылка" in Ops Center (`/api/ops/broadcast*`) uses the same runner. Admins (`ADMIN_IDS`) keep the text bot. Registration (name/phone) stays in the bot. `sheets._CachedWs` caches Sheets reads for `SHEETS_READ_CACHE_SECONDS` (12 s; any write to a sheet invalidates it) — needed so mass app opens don't exhaust the Sheets read quota.

## Меню (Операционный центр → Меню): «Меню дня» / «Каталог» / «Название сетов»
- Фото и состав сетов в черновике — отдельный лист `config.SHEET_DRAFT_CARDS` ("Меню черновик карточек", `sheets.get_draft_cards/set_draft_card/ensure_draft_cards/clear_draft_cards`): пустой на каждое новое меню, старые данные из справочника не подтягиваются. `publish_draft_menu` переносит карточки выбранных сетов в справочник (клиенты видят) и копирует в архив `config.SHEET_MENU_ARCHIVE` ("Каталог меню", `archive_menu_card` — один сет+состав = одна запись, повторная публикация обновляет фото/дату). Сеты без записи в черновике (меню через бот) не трогаются.
- «Каталог» (`/api/ops/menu/archive*`): квадраты как на Главной → карточка как у клиента → «Добавить в меню на сегодня» (сет в выбранные + фото/состав/гарниры в черновик, без публикации). Предпросмотр и редактор используют `buildAdminWideCard` (те же `.menu-wide-*` стили, что у клиента).

## PAUSE MOMENTS на Главной + просмотры
Лента PAUSE MOMENTS открыта прямо на Главной (`renderHomeMoments`, под быстрыми кнопками; блока «Сегодня в меню» на Главной больше нет); карточка Moments остаётся в Клубе, из карусели Главной убрана (фильтр `kind !== "moments"` в buildHomeNewsCarousel; композер/детали открываются через `openWizard`). Просмотры: клиент шлёт пакет id видимых постов (`/api/moments/views`, пост >50% на экране ≥1 с, один раз за открытие), лист `config.SHEET_MOMENT_VIEWS` ("Моменты просмотры": post_id, tg_id, views, last_ts); `/api/moments` отдаёт `views`/`viewers` ТОЛЬКО главному админу (`is_main_admin`), его собственные просмотры не считаются.

**Новый сет из Mini App:** «Меню дня» → «Сеты сегодня» → «+ Добавить сет» (`POST /api/ops/menu/sets`, `sheets.add_catalog_set`) пишет строку в таблицу сетов «Справочники» F:Q (первая пустая из 19): F имя, G цена, H гарнир Да/Нет, P валовая прибыль = цена − себестоимость (из неё считаются Финансы, `get_set_margins`), Q название для клиентов. Лимит — строки 2–20 (`REF_SET_TABLE_RANGE`).
**Правка сета:** в «Сеты сегодня» у каждой строки кнопка «Изменить» (`POST /api/ops/menu/catalog/{key}/edit`, `sheets.update_set_price_cost`): название для клиентов, цена и себестоимость (cost = цена − валовая прибыль из столбца P) по каждому варианту группы; техническое имя не меняется. Смена цены пишется в лист «История цен» (`config.SHEET_PRICE_HISTORY`, `_record_price_change`): новая цена действует по дате доставки заказа ≥ дня изменения, прошлые заказы остаются по старой (`_price_for` в `_row_amount`/`_order_amount`). Формула в столбце J самой таблицы пересчитается по текущей цене — приложение её игнорирует. Техническое имя можно менять (`rename_catalog_set` переименовывает его в таблице сетов, ВСЕХ заказах, избранном, истории цен, черновике/каталоге меню; название для клиентов сохраняется); у вариантов пары «X»/«X без компота» — нельзя.

**Защита от квоты Google (server_error):** `_CachedWs` теперь (1) сливает одинаковые параллельные чтения в одно обращение (per-key lock), (2) при ошибке Google (429/5xx) отдаёт последнее удачное чтение до 5 минут, TTL по умолчанию 20 с. Просмотры постов копятся в памяти и пишутся пачкой раз в ~90 с (`record_moment_views`/`_flush_moment_views`). Клиентский `api()` один раз автоповторяет GET при 503/429; ленту на Главной перезагружаем не чаще раза в 30 с.
**Рассылка о меню со своим текстом/фото:** «Текст и фото рассылки» в «Меню дня» (черновик `get_draft_menu`) теперь реально уходит клиентам: при публикации из Mini App `menu_broadcast.start(..., caption, photo_ids)` шлёт ОДНО сообщение (1 фото + подпись + кнопка, только текст + кнопка, несколько фото — альбом без кнопки; `{name}` в тексте = имя). Пусто и без фото — стандартный текст. Ручная «Рассылка» на дату активного меню берёт текст/фото, заданные при его публикации. Публикация через команды бота по-прежнему шлёт стандартный текст.

**Финансы (модель, `api_ops_summary` + `sheets._row_finance`):** по продажам, статус оплаты не важен. Выручка = блюда (оплаченные лепестком = 0) + доставка клиентов (`O_DELIVERY_FEE`); «кухня» (себестоимость) = цена − прибыль с порции × шт по ВСЕМ приготовленным блюдам, включая лепестковые (подарок за счёт PAUSE); валовая = выручка − кухня; чистая = валовая − расходы на доставку (сервисы + оплата курьерам из «Маршрут»). Отдельно: доход от доставки, лепестки (шт + себестоимость), предупреждение о сетах без себестоимости (`missing_cost_sets`). Цена и прибыль с порции берутся на дату заказа из листа «История цен» (4-й столбец — прибыль с порции; пусто/0 → текущая из таблицы).

**Оплата курьеру (Маршрут):** `pay_courier_shift` под локом; если за дату уже есть оплата — `already_paid` (409), UI спрашивает «Вы уже оплатили курьеру… заплатить ещё?», при «да» шлёт `repay` и суммирует (`pay-shift`). Антидребезг 1,5 с на фронте. В «Доход курьера» у админа «Изменить»/«Удалить» (`shift-edit`/`shift-delete`, `edit_courier_shift`/`delete_courier_shift`): оплата из наличных пересчитывается/возвращается в «Наличные у курьера» (строки «Оплата из наличных» за эту дату).
**Расходы на доставку через сервисы (Маршрут):** на экране «Расходы на логистику» кнопка «История расходов на сервисы» — список по дням (`/api/logistics/delivery-history`), «Изменить» (тот же `POST /api/logistics`) и «Удалить» (`/api/logistics/delivery-delete`, `sheets.delete_delivery_expense`).
**«Забрать наличные» на сумму:** в экране «Забрать наличные» поле «Забрать сумму» (`withdraw-cash` с `amount`, `withdraw_courier_cash_amount`): списывает с самых старых дней, больше суммы на руках нельзя (`too_much`). Выбор дней галочками остался.
**Очистка истории курьера:** кнопка «Очистить историю платежей» в карточке курьера (только владелец/главный админ; `POST /api/couriers/manage/{id}/reset-history`, `sheets.reset_courier_history`): строки «Расчёты с курьерами» и «Расходы на логистику» (оплата за смену) этого курьера копируются в лист `config.SHEET_COURIER_HISTORY_ARCHIVE` и удаляются; в «Курьеры» (столбец I `COURIER_CASH_FROM`) пишется дата «считать с» — наличные раньше неё не входят в остаток/дни (`_courier_cash_from`), но список «кто сколько дал» (`get_cash_entries`, лист «Наличные») не тронут.
**Оповещения «курьер рядом»** (`courier_notify.notify_point`): (1) «Вы следующие» — когда курьер отмечает точку «Сдано» (`api_route_complete`), клиентам следующей по порядку несданной точки ЭТОГО курьера; (2) «Подъезжаю» — кнопка у курьера (`POST /api/route/arriving`). Только клиентам с заказом на точку, с tg_id и без `notify_courier_off` (столбец U `COL_NOTIFY_COURIER_OFF`, переключатель «Курьер рядом» в уведомлениях PAUSE App); не чаще раза каждого вида в день (журнал — лист `config.SHEET_COURIER_NEAR_LOG`, «next» не шлётся после «arriving»). Общий выключатель — «Центр управления» → «Оповещения клиентам» (ячейка `REF_COURIER_NOTIFY_OFF_CELL` J10). Тексты — `texts.COURIER_*_TEXT`.
**Пуш «маршрут готов»:** шлётся только на переходе «видимость выключена → включена» (`api_route_visibility_set`) и только курьерам, назначенным на точки этой даты (столбец C «Маршрут») без `notify_off`; ручной повтор — кнопка «Уведомить» у даты в «Видимость маршрутов» (`POST /api/route/notify-couriers`, отвечает assigned/muted/notified). Новый курьер (`add_courier`) подключается ко всем несданным точкам сегодняшней/активной/будущих дат (`_backfill_courier_into_active_route`).
**Язык «Маршрута» (RU/UZ):** переключатель RU|UZ в шапке обоих экранов (`screenHeader`, `.lang-pill`). Перевод — `webapp_static/i18n.js`: русские тексты в app.js/index.html остаются исходными, при `uz` модуль подменяет их в DOM и тостах (словарь `PAIRS`: `"x"` — только полное совпадение, иначе подстрока с границами слов; МОДУЛЬ ОБРАБАТЫВАЕТ ТОЛЬКО ТО, ЧТО ЕСТЬ В СЛОВАРЕ — при добавлении нового русского текста в app.js добавляйте пару). Выбор — localStorage `route_lang_v1` (по умолчанию uz, если язык Telegram uzbek) + `POST /api/me/lang` пишет в «Курьеры» столбец J (`COURIER_LANG`), пуш «маршрут готов» уходит на этом языке (`texts.ROUTE_READY_PUSH_UZ`). Названия сетов (бренд) не переводятся.
**ОБНОВЛЕНИЕ «курьер рядом» (заменяет описание выше):** «Вы следующие» по «Сдано» УБРАНО. Теперь у активной точки курьера три шага-кнопки (`buildStepButtons`): 1 «Поехали» (`POST /api/route/going` → клиентам «курьер выехал», `texts.COURIER_GOING_TEXT`; плюс открывает карту и пишет старт), 2 «Подъезжаю» (`/api/route/arriving`), 3 «Сдано». Ответ курьеру мгновенный (`courier_notify.trigger` считает получателей и ставит отправку в фон, параллельно 8 потоков); состояние шагов хранится в журнале «Оповещения курьера» строками с клиентом `*` (`get_courier_steps`, отдаётся в `/api/route` как `steps`) и переживает перезагрузку.
**Кнопки курьера вернули к привычному виду** (шаги 1–2–3 убраны): ряд «Поехали» | «Сдано», ниже «Подъезжаю» | «Наличные». Нажатые «Поехали»/«Подъезжаю» становятся зелёными «✓ Выехал · 12:30» / «✓ Подъезжаю · 12:41» + тост «Клиентам отправлено: N» (`markStepBtn`/`sendStep`); состояние хранится в журнале «Оповещения курьера» (см. выше). Тексты: «Поехали» → `COURIER_GOING_TEXT`, «Подъезжаю» → «курьер будет у вас примерно через 5 минут. Встречайте.»
**«Новая точка» vs существующая:** метка на карте в пределах `KNOWN_POINT_RADIUS_M` (60 м) от точки из «Точки доставки», либо то же имя, больше не считается новой и не уходит админу на подтверждение: сервер (`_resolve_known_point` в `api_order_submit` и `api_profile_edit`) подставляет имя/район существующей точки, клиент (`renderDeliveryMapPicker`) делает то же до отправки.
**Устойчивость к «server error»:** `_retry_sheets` (webapp.py, им же пользуется pauseapp) — 4 повтора с экспоненциальной паузой (1.2→1.9→3.1→4.9 с) вместо 2 коротких; скан «бывших курьеров» (`_former_couriers`) кэшируется на 3 минуты (раньше читал 4 листа на каждое обновление `get_couriers`, а оно дёргается на каждом запросе курьера); в «Маршруте» `api()` автоповторяет GET и POST с флагом `idempotent` один раз при 503/429.
**Оценка доставки:** при «Сдано» (`api_route_complete` → `courier_notify.notify_delivered_bg`) клиентам точки уходит (в фоне, раз в день) двуязычное «ваш обед доставлен, оцените доставку» с кнопкой `kb.rate_delivery_kb` → PAUSE App `?rate=ДД.ММ.ГГГГ` открывает окно `openDeliveryRating` (звёзды + комментарий; отдельного входа в приложении нет, кнопка «★ Отзыв» в «Мои заказы» убрана). `POST /api/delivery-rating` пишет в лист `config.SHEET_DELIVERY_RATINGS` («Оценки доставки», одна запись на клиента и дату, повтор правит) и шлёт админам в бот `texts.ADMIN_DELIVERY_RATING_ALERT`. Для админа: Операционный центр → «Оценка доставки» (даты со средней оценкой → оценки/комментарии за день; `/api/ops/delivery-ratings*`, главному админу и `pa_finance`). Общий выключатель оповещений «курьер рядом» и личный переключатель клиента действуют и на это сообщение.

**Ответы на комментарии в PAUSE MOMENTS:** у комментария кнопка «Ответить» (`renderMomentDetail`, чип «Ответ для …»); `POST /api/moments/{id}/comments` принимает `reply_to` (id комментария), в листе «Моменты комментарии» столбцы H `reply_to`, I `reply_name`. Автору комментария, на который ответили, уходит уведомление в колокольчик (`moment_comment:<post>`) и сообщение в бот (`texts.MOMENT_REPLY_BOT`, кнопка `kb.open_pause_app_kb`); автору поста — обычное «прокомментировал», если он не тот же человек.

**Доставка для ручных заказов:** `sheets.autofill_manual_delivery` (бот, планировщик каждые 2 мин): для клиента+даты (сегодня и позже) без метки оформления AC и без доставки пишет в AD на первую строку сумму по уровню клуба (`get_client_delivery_fee`). Заказы приложения/бота (есть AC) и старые даты не трогаются. Доставку для конкретного клиента можно убрать, вписав в AD на его строку `0`... — пустое поле будет заполнено снова, поэтому для «бесплатно» ставьте в AC любую метку.

**Счётчик заказов клиента:** `order_count` в `_load_clients` = max(значение формулы Sheet1 «Кол-во Заказов», реальный подсчёт `_order_counts_from_orders` — сумма «Кол-во» по неотменённым строкам «Заказы»). От него зависят уровень клуба и платная доставка; формула в таблице может «залипнуть» (текстовые числа, затёртая формула) — приложение это переживает.

**Автоисправление «Кол-во Заказов» в Sheet1:** `sheets.sync_client_order_counts` (бот, раз в 10 мин и через 30 с после старта): там, где в столбце O стоит вписанное число, а не формула, пишет реальное число порций из «Заказы» (так «залипло» у ID 63: 20). Ячейки с формулой не трогает.

**Поздравление с новым уровнем клуба:** бот каждые 5 мин (`bot.py: _level_ups`, `sheets.find_level_ups`) сверяет уровень клиента с листом `config.SHEET_CLUB_LEVEL_LOG` («Уровни клуба»: tg_id, id, уровень, дата). Первый запуск и новые клиенты записываются молча; при переходе вверх — сообщение в бот (`texts.LEVEL_UP_TEXTS`, свой текст на каждый уровень, доставка из `CLUB_DELIVERY_FEES`, кнопка «Открыть PAUSE») + запись в колокольчик (`texts.LEVEL_UP_BELL`, kind `level_up`). Уважает общий выключатель рассылок; не отправленное повторится при следующем проходе.

**Лепесток только на «Для тебя»:** `config.PETAL_ALLOWED_SETS` ({"для тебя"}, без регистра/точек, по клиентскому или техническому имени). Сервер (`api_order_submit`, `_petal_allowed_set`) отвечает `ticket_set_not_allowed` (400); в оформлении (`stepCheckout`) плитка «Лепестком» появляется только если в корзине есть «Для тебя», выбирается только такая позиция. Тексты про лепесток (ru/uz/en) обновлены.

**Порядок карточек меню:** на «Предпросмотре» в «Меню дня» у каждой карточки кнопки «↑ Выше»/«↓ Ниже» (`renderMenuDraftPreviewStep`) — порядок сохраняется тем же `POST /api/ops/menu/draft/sets` (порядок в ячейке черновика), при публикации переходит в «сегодняшние сеты», клиентское меню (`api_menu` → `_serialize_sets`) идёт в этом порядке.

**Свои аватарки:** тап по аватарке в профиле открывает полноэкранный просмотр (`openAvatarViewer`) с «Сменить фото» (выбор → центр-кроп 512×512 на фронте, `avatarSquare` → `POST /api/profile/avatar` → Telegram-хранилище `MEDIA_CHAT_ID`, file_id в листе `config.SHEET_AVATARS` «Аватарки»: tg_id, file_id, дата) и «Вернуть фото из Telegram» (`POST /api/profile/avatar/delete`). `api_avatar_image` (лидерборд, Моменты, профиль) сначала отдаёт свою аватарку, потом фото профиля Telegram; `/api/profile` отдаёт `custom_avatar`. Только зарегистрированным клиентам.

**CRM → Карта:** Операционный центр → CRM → «Карта» (только главный админ; `renderCrmMap`, `GET /api/crm/map`, `sheets.get_crm_points_map`): Leaflet с метками точек из «Точки доставки» (число — сколько клиентов, у которых это точка по умолчанию в Sheet1). Тап по метке → название → шторка снизу со списком людей (имя, телефон, @юзернейм, справа значок письма → `openTelegramChat`: `https://t.me/<username>`, иначе `tg://user?id`). Точки клиентов без координат/нет в «Точки доставки» перечислены под картой («Не на карте»).

**Наличные: кто дал (админ, «Маршрут»):** в раскрытой карточке точки у админа кнопка «💵 Наличные: кто дал» (`openAdminCashModal`): список записей листа «Наличные» по точке и дате (клиент, сумма, курьер, время; `GET /api/cash/point-entries`, `sheets.get_point_cash_entries`), тап по записи — правка суммы / удаление (`/api/cash/admin-edit|admin-delete`, проверка клиента+даты по номеру строки, иначе 409), «+ Добавить наличные» задним числом (`/api/cash/admin-add` → `record_cash_collection`, курьер — назначенный на точку). Удаление записи НЕ возвращает заказам статус «не оплачено».

**«Общая сумма у курьера» — журнал по дням:** вместо строки «Собрано всего − забрали…» под суммой (карточка курьера у админа, `renderBoxes`) — список дней до выбранной даты (`sheets.get_courier_cash_ledger`, отдаётся в `/api/courier/cash-summary` как `ledger`): собрал / забрали / оплачено из наличных / оплачено отдельно и «Остаток» на конец дня нарастающим итогом; дни без движений тоже есть, максимум 31 день (раньше — «Остаток на начало»).

**«Должники» — пакетное удаление истории:** долгое нажатие на человека с долгом 0 включает режим выбора (дальше выбирается обычным тапом; с долгом > 0 выбрать нельзя), вверху панель «Выбрано: N · Удалить историю · Отмена» (`loadOpsDebtorsList`) → `POST /api/ops/debtors/delete-history-batch` (`sheets.delete_debtors_history`, пропускает клиентов с живым долгом; одиночное `delete_debtor_history` использует её же).

**Фото рассылки меню — до 10:** в «Текст и фото рассылки» новые фото ДОБАВЛЯЮТСЯ к уже выбранным (раньше каждый выбор заменял прежние), у каждого есть «×»; сервер (`api_ops_menu_draft_photo`) принимает поле `keep` (индексы прежних фото, которые остаются) + новые `photo`, максимум 10. Больше одного фото уходит клиентам альбомом (подпись — на первом фото, кнопки у альбома нет — ограничение Telegram, поэтому следом отдельным сообщением «🌿» с кнопкой «Посмотреть меню 🌿»).
Сохранение фото рассылки: перед отправкой фото уменьшаются (`momDownscale`, 1600 px JPEG), сервер заливает их в Telegram параллельно (`asyncio.gather`), у запроса таймаут 90 с с сообщением об ошибке — оригиналы по 5–10 МБ раньше грузились «бесконечно».
Ручная «Рассылка» (`api_ops_broadcast_menu`): если в «Текст и фото рассылки» (черновик) что-то задано — берёт его (а не текст/фото, заданные при публикации) и после запуска очищает черновик; иначе — как при публикации.

**«Без приборов» при оформлении:** переключатель-карточка над комментарием (`buildNoCutleryRow`, `checkout.noCutlery`, выбор запоминается в localStorage `pause_no_cutlery_v1`); при отправке в комментарий для кухни дописывается «Без приборов» (`checkoutCommentForKitchen`, всегда по-русски, не дублируется, если клиент уже написал сам).

**Оформление заказа — новый вид (`stepCheckout`):** адрес одной карточкой (`.co-addr`, «Изменить» чипом внутри), блок «Пожелания» (`.co-list`: переключатель «Без приборов» + сворачиваемые «Комментарий к заказу»/«Комментарий к доставке» — раскрываются по тапу, раскрыты, если в них уже есть текст; флаги `checkout.commentOpen/deliveryCommentOpen`), «Сверка заказа» компактным списком без строки «Итого» (итог — в кнопке), оплата плитками с иконками (`.co-pay-tile`, выбранная залита тёмным), закреплённая нижняя панель `.co-bar` с кнопкой «Подтвердить заказ · сумма» (`.co-cta`, сумма не показывается, если всё покрыто лепестком).

**Смена Telegram ID курьера:** в карточке курьера («Курьеры», только владелец/главный админ) кнопка «Сменить Telegram ID» → `POST /api/couriers/manage/{tg_id}/replace-id` (`sheets.replace_courier_tg_id`): меняет ID в листах «Курьеры», «Маршрут» (столбец C, список через запятую, без дублей), «Старт маршрута», «Наличные», «Расходы на логистику», «Расчёты с курьерами» — история и касса остаются у того же курьера. Если новый ID уже есть среди курьеров — `new_exists` (409).

**Уведомления админам о заказах + кнопка «Заказы»:** о КАЖДОМ заказе из PAUSE App админам (`ADMIN_IDS`) уходит «🛒 Новый заказ» (`pauseapp._notify_new_order`, `texts.new_order_alert`: клиент, username/телефон, точка, состав, доставка, сумма, способ оплаты). Если приложен скрин — уходит только скрин с подписью как раньше (`_notify_screenshot`), второго сообщения нет; заказ на новую точку — как раньше (заявка на подтверждение). В текстовом боте (панель /admin и `/orders [дата]`) кнопка «🧾 Заказы» → выбор даты (`report_dates_kb("orders")`) → список клиентов за дату (`sheets.get_orders_for_date`, `handlers/admin._send_orders_for_date`): контакты, точка, состав, сумма, оплата (✓ — подтверждена); заказы со скрином тоже в списке, а «Подтверждение оплаты» работает как раньше. Заказы из чат-бота (`handlers/order.py`) этим не менялись.

**Заказ без отсечки:** `config.NO_CUTOFF_TG_IDS` ({"614897018"}) — эти tg_id могут заказывать в любое время (PAUSE App: `api_menu`, `api_order_submit`; чат-бот: `handlers/order.py`), приём заказов для них не закрывается.

**Реквизиты при оплате картой (`buildRequisitesCard`):** светлая карточка `.req-card` — подпись «Номер карты», номер крупно, имя серым, кнопка «Скопировать» кладёт в буфер ТОЛЬКО номер (цифры без пробелов и без имени; `copyToClipboard` с запасным `execCommand`). Номер — первая строка из 13–23 цифр/пробелов в `card_requisites`; если такой строки нет, показывается весь текст без кнопки. Ключи `checkout.req*` (ru/uz/en).

**«Мои заказы» — закреплённый долг:** при долге внизу окна закреплена тёмная плашка `.debt-bar` (sticky, как `.co-bar`): «Текущий долг» + сумма и кнопка «Оплатить» → `openDebtPay` (ключи `orders.debtLabel/payBtn`).

**Статус Pause Club — по ДНЯМ с заказами, не по порциям:** `sheets._order_days_from_orders` (число разных дат доставки с неотменённым заказом, 10 сетов за день = 1 день) → `client["club_count"]` (`sheets.club_count_of`) — от него считаются уровень, платная доставка, допуск к розыгрышу, поздравления, бейдж в рейтинге, прогресс в «Pause Club» (`club.count` в `/api/profile`). Пороги прежние (1/10/25). `client["order_count"]` остаётся ПОРЦИЯМИ — для «Профиль»/CRM/рейтинга (рейтинг по-прежнему ранжируется по порциям). **Никто не падает:** при первой загрузке клиентов после перехода `_load_status_floor` один раз пишет в лист `config.SHEET_CLUB_STATUS_FLOOR` («Статус клуба (зафиксировано)») для каждого клиента порог его прежнего уровня (по порциям) и число дней на этот момент (+ строка-маркер `_snapshot`); дальше `club_count = max(дни, порог + дни после фиксации)`. Если данные заказов не прочитались — фиксация откладывается, временно `max(порции, дни)`. Побочный эффект: второй заказ в тот же день уровень не поднимает (доставка того же дня считается по тому же уровню).

**Каталог меню — правка отдельно от публикации:** в карточке каталога кнопка «Изменить» (фото и состав; `renderMenuArchiveEditor`, `POST /api/ops/menu/archive/{id}/photo|description`, `sheets.update_menu_archive` — id зависит от сета+состава и пересчитывается, дубль того же сета и состава вливается) и «+ Добавить карточку» вверху каталога (выбор блюда → фото/состав; `POST /api/ops/menu/archive/add`, `sheets.add_menu_archive_blank`). Меню дня при этом не трогается.

**Каталог — сначала по сетам:** на входе плитки «Пауза дня», «Для тебя»… (любое фото из сета + число карточек), тап → все карточки этого сета (`renderMenuArchiveGroup`, там же «+ Добавить карточку» сразу для этого сета), дальше как раньше: карточка → «Изменить»/«Добавить в меню»/«Удалить».
